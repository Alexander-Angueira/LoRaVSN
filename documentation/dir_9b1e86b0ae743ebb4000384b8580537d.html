Detailed Description

Gateway — Python LoRaWAN Communication

Python implementation of the Raspberry Pi 5 Gateway communication layer. It talks to the REYAX RYLR998 module over UART using pyserial and exposes the same <payload_type>,<packet_id>,<payload> message format used by the ESP32 Remote Node, so both ends of the link share a single wire protocol.

Requirements

Wire format

Every payload sent through the LoRa network follows the format

<payload_type>,<packet_id>,<payload>

<payload> is plain ASCII and is allowed to contain ,, ; or \n. Because of that, only the first two commas are treated as field separators — everything after the second comma is preserved verbatim. On the receiving side the +RCV length field is used to slice the payload so that newlines inside the payload do not truncate the frame.

Running the examples

The examples must run on the Raspberry Pi 5 with the RYLR998 connected to the GPIO UART (/dev/ttyAMA0). See loravision/docs/rpi5_setup.md for the full Pi setup.

Send a message to a single peer (Remote Node at address 2):

python loravision/gateway/python/examples/01_send_message.py --peer 2

Receive every incoming message and print it to stdout:

python loravision/gateway/python/examples/02_receive_message.py

Both scripts accept --port, --baud, --address and --network-id overrides if the defaults in loravsn/config.py do not match your setup.

Sending to multiple Remote Nodes

LoRaRadio.send_message accepts either a single integer address or a list of addresses, which is the building block for the point-to-multipoint operation required by the gateway:

from loravsn import LoRaRadio, Message, MessageType
with LoRaRadio.open() as radio:
radio.begin()
msg = Message(MessageType.COMMAND, 0, "ping")
radio.send_message(msg, address=[2, 3, 4]) # one transmission per peer
# or, to flood the network:
radio.broadcast_message(msg)

Running the tests

The tests are pure-Python and do not require a physical RYLR998 module — the serial port is replaced with a small FakeSerial double that scripts the responses the firmware would normally return.

From this directory:

python -m unittest discover -s tests -v

Or from the repository root:

python -m unittest discover -s loravision/gateway/python/tests -v
