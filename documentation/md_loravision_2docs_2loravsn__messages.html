LoRaVSN Messaging Format

A LoRaVSN message adds an additional header to the standard message format implemented by the REYAX RYLR998 LoRa Module.

REYAX RYLR998 LoRa Module Sent Message:
AT+SEND=<address>,<length>,<data>
LoRaVSN Sent Message:
AT+SEND=<address>,<length>,<message_type>,<packet_id>,<data>
REYAX RYLR998 LoRa Module Received Message:
+RCV=<address>,<length>,<data>,<rssi>,<snr>
LoRaVSN Received Message:
+RCV=<address>,<length>,<message_type>,<packet_id>,<data>,<rssi>,<snr>

This additional header allows the system to categorize and handle incoming messages quickly and with less boilerplate through the message_type, and allows reconstructing messages in the same order they were sent, and identifying missing data packets, through their packet_id.

NOTE: The packet_id property, although present in all messages, it's really only use with data packets. For other message types the property is ignored.

Message Fields Definitions

Field Range Description
address 0-65535 Sender or recipient address.
length 0-240 Length of data + len(message_type) + len(packet_id) + 2 for commas.
message_type NA Type of message. Must have length 3.
packet_id 0-999 Sequential packet identifier.
data NA Message data ASCII encoded.

Message Types

Message Type Message Type Label Description
Info INF Used in handshakes before sending data packets, informs the receiver the amount of data packets to be transferfed by the sender.
Error ERR Used for sending error messages through the LoRaVSN network.
Request REQ Used for requesting data from a LoRaVSN system component (i.e., a Remote Node or Gateway).
Data DAT Used for sending data packets.
Acknowledge ACK Used for confirming a message was received.
Command CMD Used for altering a configuration or trigger a behavior.
Unknown UNK Fallback for when a received message type is not known.

Implemented Messages and Examples

Start an Image Data Request or an ROI Data Request

REQ: IMGDAT
REQ: ROIDAT

Request Image Data Retransmission

REQ: IMGDAT=<specific_packet0>,<specific_packet1>,<specific_packet2>,...
REQ: ROIDAT=<specific_packet0>,<specific_packet1>,<specific_packet2>,...

Transmission Handshake

INF: IMGDAT=<packet_count>
INF: ROIDAT=<packet_count>

Send a Command

CMD: ROIRST // Reset ROIs in Remote Node
CMD: ROISTP // Stop ROI extraction in Remote Node
CMD: ROISTR // Start ROI extraction in Remote Node
CMD: THRPUT // Start throughput test in Remote Node
CMD: PCKTSZ=<packet_size> // Set the maximum packet size in Remote Node.

Acknowledge a Message

ACK: <ack_label> // Label of message ack'ed (e.g., ROIRST, IMGDAT=<packet_count>, ...)

Implementation Details

The LoRaVSN messaging format is implemented by the classes IncomingMessage and OutgoingMessage in both the Gateway and Remote Node. The following distinctions are important regarding these implementations message_length and payload_length properties.

Example message:
+RCV=1,14,DAT,2,Hello!,-63,11
LoRaVSN content:
DAT,2,Hello!
message_length = 12
payload_length = 6

End-to-End Example

Gateway:
AT+SEND=2,12,REQ,0,IMGDAT
Remote Node:
+RCV=1,12,REQ,0,IMGDAT,-63,11
AT+SEND=1,14,INF,0,IMGDAT=3
Gateway:
+RCV=2,9,INF,0,IMGDAT=3,-63,11
AT+SEND=2,14,ACK,0,IMGDAT=3
Remote Node:
AT+SEND=1,11,DAT,0,Hello
AT+SEND=1,11,DAT,1,World
AT+SEND=1,7,DAT,2,!
Gateway:
+RCV=2,11,DAT,0,Hello,-63,11
+RCV=2,11,DAT,1,World,-64,10
+RCV=2,7,DAT,2,!,-65,9
